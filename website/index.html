02 / QUICK START

Begin with one declared workflow.

Install only what the first slice needs. Add adapters and control planes as the application grows.

A

Create a consumer

Hypha packages are libraries. Your application owns its DomainPack, prompts, skills, adapters, and deployment configuration. 

mkdir my-hypha-agent && cd my-hypha-agent
npm init -y
npm install \
  @codesoul-co/hypha-domain@1.0.0 \
  @codesoul-co/hypha-kernel@1.0.0 \
  @codesoul-co/hypha-harness@1.0.0 \
  @codesoul-co/hypha-adapters-local@1.0.0
B

Compile the product contract

A DomainPack compiles product evidence into explicit Agent, capability, policy, memory, and evaluation bindings. ReAct keeps the protected Harness FSM; custom Runs bind a separately validated application FSM. 

import {
  compileDomainPackToHarnessedSystem,
  loadDomainPackFile,
} from '@codesoul-co/hypha-domain';

const pack = await loadDomainPackFile('agent/domain-pack.yaml');
const system = compileDomainPackToHarnessedSystem(pack, {
  agentRef: { id: 'agent.research', version: '1.0.0' },
  taskSchemaId: 'task.research',
  workflowId: 'workflow.research',
});

console.log(system.fsmProcess, system.bindings);
// system.fsmProcess is the protected ReAct Harness process.
// See “FSM control” for a custom application topology.

05 / FSM CONTROL

You define topology.
The harness guards motion.

Application-defined node names and edges are supported. Manual transitions are owner-governed commands, not direct state mutation.

  1. Declare

    Define states, kinds, transitions, guards, timeouts, retries, and terminal states in an FSMProcessSpec or DomainPack workflow.

  2. Inspect

    analyzeFSMTopology() reports reachable, unreachable, dead-end, and cyclic states before execution.

  3. Advance

    Use the runtime transition endpoint with process identity, expected state, expected Run revision, target state, reason, and idempotency key.

  4. Replay

    Every accepted or rejected transition remains explainable from Events and transition evidence.

Each slice has a narrow verification target. The final application combines them without collapsing package boundaries.

RUNBOOK / RELEASE AGENT

From clone to governed Run

  1. cd examples/release-agent && npm installInstall the same 1.0.0 line for every Hypha package.
  2. npm run tour && npm testExercise every package boundary and deterministic DomainPack compilation.
  3. npm run compile-agentInspect the compiled Agent, bindings, and custom FSM.
  4. HYPHA_CONFIG_PATH=... npm run devStart a separate Hypha Server checkout with the product overlay.
  5. npm run run -- "What makes events authoritative?"Submit a durable ReAct Run through the HTTP surface.
  6. npm run run:fsmInspect revision and apply one governed owner transition.

08 / PRODUCTION

Ship with evidence,
not assumptions.

A production deployment should be able to answer what ran, who authorized it, which revisions were bound, and how state can be rebuilt.

VERSION DISCIPLINE

Keep every @codesoul-co/hypha-* dependency on one release line. This guide documents 1.0.0. Pin exact versions in production applications and update through an explicit replay/regression gate.
